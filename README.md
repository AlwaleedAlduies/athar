# أثَر | ATHAR

تطبيق Django يعمل بقاعدة بيانات فعلية لاستكشاف التاريخ الإسلامي، بواجهة عربية RTL، وصلاحيات «أمين معرفة» و«مستكشف»، وتتبّع للادعاءات إلى أدلتها ومصادرها.

**لا تقرأ التاريخ فقط... عِش أثره.**

## التشغيل السريع

يتطلب Python 3.12 أو أحدث. من مجلد `athar`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
Copy-Item .env.example .env
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo
.\.venv\Scripts\python.exe manage.py import_dorar_pilot --apply
.\.venv\Scripts\python.exe manage.py enrich_medina --apply
.\.venv\Scripts\python.exe manage.py enrich_stories --apply
.\.venv\Scripts\python.exe manage.py create_demo_admin
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

افتح <http://127.0.0.1:8000/>. للدخول إلى الإدارة: <http://127.0.0.1:8000/dashboard/>.
الأمر `create_demo_admin` يطلب كلمة مرور قوية ولا يحتوي على كلمة افتراضية. يمكن تمرير اسم المستخدم بـ `--username`، أو توفير كلمة المرور مرة واحدة في متغير البيئة `ATHAR_ADMIN_PASSWORD`. لا يغيّر الأمر حسابًا موجودًا.

في Windows يمكن تشغيل `./start.ps1` بعد الإعداد؛ ينشئ البيئة إن كانت غير موجودة، ويطبّق الترحيلات وبيانات العرض، ثم يبدأ الخادم. لتغيير المنفذ: `./start.ps1 -Port 8002`.

على Linux/macOS استبدل `.venv\Scripts\python.exe` بـ `.venv/bin/python`.

في نسخة مساحة العمل الحالية أُنشئ حساب إدارة محلي، وبياناته في `.local-access.txt` المستبعد من Git ومن Docker. لا تُنشر هذا الملف. قاعدة البيانات المحلية والملفات المرفوعة والأسرار مستبعدة أيضًا.

## ما الذي يعمل؟

- تسجيل حساب، دخول وخروج، تعديل الملف، محفوظات خاصة، سجل استكشاف وسجل بحث.
- صفحة تعريف، اكتشاف، خط زمني قابل للبحث والترشيح، صفحات أحداث وشخصيات وأماكن ومصادر وعصور.
- تجربة حدث بأقسام السياق والأسباب والقرارات والنتائج والأحداث المتصلة.
- خريطة SVG تفاعلية تعتمد على علاقات قاعدة البيانات، مع مرشحات وروابط قابلة لاستخدام لوحة المفاتيح.
- نافذة «تتبّع الدليل»: نص الادعاء، التصنيف، المقتطف، المصدر، القسم والصفحة إن عُرفا، نوع الدعم والروايات الأخرى وحالة المراجعة.
- بوابة إدارة عربية مستقلة: CRUD، أرشفة، اعتماد ونشر، ربط الشخصيات والأماكن والمصادر، مراجعة اقتراحات المرشد، المستخدمون وسجلات الأسئلة.
- رفع PDF النصي وTXT بترميز UTF-8 وDOCX؛ استخراج النص وتقسيمه وتخزين المتجهات مع أصل كل مقطع.
- مرشد RAG قابل لتهيئة OpenAI أو Gemini أو Ollama، مع وضع استخراج نصي حقيقي دون مفاتيح.
- محاكاة تعليمية منفصلة، تتطلب تأكيدًا، تعرض محتوى معدًا مسبقًا دون مزوّد، وتستدعي المزوّد عند تهيئته.
- تطبيق الصلاحيات والتحقق من البيانات وCSRF على الخادم، تجنّب HTML غير الموثوق، وحدود ملفات ومعدل أسئلة.

## بيانات العرض والثقة التاريخية

الأمر `seed_demo` ينشئ ثلاث تجارب: **الهجرة، غزوة بدر، صلح الحديبية**. يستخدم `get_or_create` ولا يستبدل تحرير المسؤول عند تكراره. جميعها تحمل `is_demo=True` وتظهر كمحتوى يحتاج مراجعة المصدر، بما في ذلك التواريخ والعلاقات. لا توجد أقوال منسوبة أو ادعاءات تاريخية تفصيلية مخترعة.

عنصر «مساحة المصدر — بانتظار التوثيق» نموذج واجهة، وليس مرجعًا. لا يُعتمد ولا يدخل RAG. الادعاء التجريبي يشرح التتبّع، وتعرض نافذته نقص الأدلة صراحة. لا يُنشئ البذر مصادر تاريخية معتمدة تلقائيًا.

**في قاعدة تحتوي بيانات seed_demo وحدها يُجاب عن سؤال الحديبية بعدم كفاية الأدلة.** لتقديم إجابة مصدرية في العرض، يرفع أمين المعرفة مصدرًا يحق له استخدامه، ويتحقق منه، ويربطه بالحدث ويعتمده. هذا مقصود امتثالًا لقاعدة «الذكاء الاصطناعي ليس المصدر». يمكن إخفاء جميع التجارب باستخدام `DEMO_MODE=false`.

النشر الحقيقي للحدث يتطلب ادعاءً معتمدًا. اعتماد الادعاء غير التجريبي يتطلب دليلًا من مصدر معتمد؛ اعتماد «حقيقة» يتطلب دعمًا مباشرًا وعدم وجود دليل معارض غير محسوم. سحب اعتماد المصدر يستبعده فورًا من RAG والتتبّع، ويسقط وصف «حقيقة موثقة» في نافذة الدليل عند زوال الدعم.

## رحلة الإدارة الكاملة

1. سجّل الدخول وافتح «أمانة المعرفة».
2. أضف حقبة، وشخصيات وأماكن؛ اعتمد ما تريد إظهاره.
3. أنشئ الحدث كمسودة، ثم اربط الشخصيات والأماكن.
4. أضف المصدر وبيانات الطبعة، وارفع ملفًا لا يتجاوز 10 MB.
5. احفظ المصدر، ثم اضغط «معالجة المصدر للاسترجاع». افتح المقاطع لمعرفة أرقامها ومواضعها.
6. بعد المراجعة، اجعل حالة المصدر «معتمد» أو «منشور»، وفعّل «مصدر معتمد للاسترجاع»؛ ألغِ الوسم التجريبي إذا كان المحتوى محققًا بالفعل.
7. اربط المصدر بالحدث، وأنشئ ادعاءً كمسودة.
8. أضف دليلًا: اختر الادعاء والمصدر والمقطع، وانسخ المقتطف بدقة. رقم الصفحة يجب أن يطابق المقطع؛ اتركه فارغًا لملفات TXT/DOCX عندما لا توجد صفحة موثوقة.
9. عد للادعاء واعتمده، ثم انشر الحدث. يظهر فورًا للمستكشف.
10. أنشئ علاقات الخريطة في سجل «العلاقات» واعتمدها. علاقات الرسم مستقلة عن قوائم الارتباط التحريرية، ولا تستنتج السببية تلقائيًا.

لا يمكن استبدال ملف مصدر ذي مقاطع محفوظة، ولا إعادة معالجة مقاطع مستخدمة في أدلة؛ أضف إصدار مصدر جديد للمحافظة على ثبات الاستشهادات. «اقتراح مسودة من المصادر» ينشئ مسودة غير معتمدة فقط.

## المعمارية والنماذج

| الوحدة | المسؤولية والنماذج |
|---|---|
| `accounts` | `User`, `UserProfile`, `Bookmark`, `ExplorationHistory`, `SearchHistory` |
| `history` | `Entity`, `HistoricalEra`, `HistoricalEvent`, `HistoricalPerson`, `HistoricalPlace`, `StoryPassage`، البحث وصفحات الاستكشاف وواجهات API |
| `sources` | `HistoricalSource`, `SourceChunk`، التحقق من الملفات ومعالجتها |
| `knowledge` | `HistoricalClaim`, `Evidence`, `EntityRelationship`، انتقاء الأدلة ورسم العلاقات |
| `ai` | `AIConversation`, `AIMessage`, `AIQueryLog`، RAG، المزودون والتضمين والتعليمات والتحقق من المخرجات |
| `simulations` | `SimulationScenario`، نشاط افتراضي منفصل عن الادعاءات |
| `dashboard` | بوابة الإدارة ونماذج المراجعة و`SystemSetting`, `ExtractionRun` |

`Entity` أصل مشترك متعدد الجداول: تحتفظ الأنواع بتفاصيلها في جداول مستقلة، بينما تشير المحفوظات والعلاقات إلى مفتاح أجنبي حقيقي في `Entity`. يفرض النظام قيود تفرد على المحفوظات والزيارات والعلاقات وترتيب المقاطع، ويمنع علاقة العنصر بنفسه. الترحيلات مرفقة.

لا منطق AI داخل القوالب؛ خدمات `apps/ai/services.py` و`providers.py` و`embeddings.py` منفصلة. صفحات Django تعمل مباشرة، وتضيف JavaScript التتبّع والخريطة والأسئلة والمحاكاة دون إطار frontend كبير.

## RAG والمتجهات

المصدر المعتمد ← مقاطع مع مواضعها ← ترشيح حسب اعتماد المصدر وسياق الحدث ← بحث متجهي ولفظي ← أدلة وعلاقات ← المزوّد أو الاستخراج النصي ← تحقق المراجع ← إجابة منظمة.

`EMBEDDING_BACKEND=hash` هو الافتراضي: متجهات لفظية ثابتة بطول 256 مخزنة في JSON داخل قاعدة البيانات، مع تشابه جيب التمام ومطابقة الكلمات العربية. **ليس هذا نموذج تضمين دلالي متعلمًا.** يفيد العرض المحلي الصغير دون تحميل نماذج أو مفاتيح.

للتضمين الدلالي المحلي:

```dotenv
EMBEDDING_BACKEND=ollama
LOCAL_LLM_URL=http://127.0.0.1:11434
EMBEDDING_MODEL=<installed-multilingual-embedding-model>
```

ثبّت نموذج تضمين مناسبًا للعربية في Ollama، ثم عالج المصادر. تُحفظ هوية النموذج مع كل مقطع؛ لا تُخلط متجهات نماذج مختلفة. عند تبديل النموذج أنشئ إصدارات جديدة للمصادر ذات الأدلة، أو أعد معالجة المصدر إذا لم تُستخدم مقاطعه في أدلة.

المخزن الحالي يفحص المتجهات في الذاكرة لكل طلب بعد ترشيحها، وهو مناسب لـMVP. لا يلزم pgvector للتشغيل. الانتقال إلى فهرس pgvector أو بحث ANN ضروري عند نمو المكتبة. البحث العام حاليًا يطبّع الهمزات والياء والتشكيل، ويرتّب التطابق ثم البادئة والكلمات والتشابه النصي، ويعامل ة/ه كتطابق ثانوي؛ عند تهيئة Ollama يضاف تطابق دلالي أخير عبر مقاطع المصادر المعتمدة، ويعيد المصادر والأحداث المرتبطة بها؛ ولا يطغى على التطابقات اللفظية.

## إعداد المرشد

الافتراضي:

```dotenv
LLM_PROVIDER=extractive
EMBEDDING_BACKEND=hash
```

يعرض مقتطفات فعلية من مصادر معتمدة، مع تسميته استخراجًا نصيًا. لا تُنشأ إجابة زائفة لإيهام المستخدم بوجود LLM.

اختر أحد المزودين وحدد اسم نموذج متاح في حسابك، يدعم الواجهة المستخدمة:

```dotenv
LLM_PROVIDER=openai
LLM_MODEL=<model-with-chat-completions-json-support>
OPENAI_API_KEY=<your-key>
```

```dotenv
LLM_PROVIDER=gemini
LLM_MODEL=<your-gemini-model>
GEMINI_API_KEY=<your-key>
```

```dotenv
LLM_PROVIDER=local
LLM_MODEL=<installed-ollama-chat-model>
LOCAL_LLM_URL=http://127.0.0.1:11434
```

تُقرأ المفاتيح من البيئة فقط، ولا ترسل إلى المتصفح. مهلة اتصال المزوّد 35 ثانية. لا يجرّب التطبيق مزودًا مدفوعًا آخر تلقائيًا. فشل الاتصال أو JSON أو مراجع غير مسترجعة ينتج حالة تعذّر واضحة، دون نشر المخرجات.

المزوّد يعيد فقرات تحمل `chunk_ids`؛ يتحقق الخادم من أن كل فقرة غير فارغة وكل معرف ينتمي إلى المقاطع المسترجعة، ثم يبني المصادر والصفحات من قاعدة البيانات. **صحة المعرف لا تثبت الاستلزام الدلالي لكل جملة**؛ لذلك تظل الشروح المولدة «تفسيرًا يحتاج مراجعة»، ولا تتحول تلقائيًا إلى حقائق موثقة. اختبارات نجاح التوليد تستخدم مزودًا بديلًا مضبوطًا. أُجريت مكالمات حية بالمفتاح المحلي؛ رفض Gemini التوليد برمز 403 وسبب project_access_denied. لم تُعرض نتيجة الاختبار البديل على أنها نجاح للمزوّد الحي.

ترجع خدمة السؤال:

```json
{
  "answer": "...",
  "classification": "UNCERTAIN",
  "sources": [],
  "evidence": [],
  "related_entities": [],
  "confidence": "الأدلة غير كافية",
  "needs_review": true,
  "mode": "extractive",
  "segments": []
}
```

لا تُعرض نسب ثقة مصطنعة. تسجّل الأسئلة والمقاطع المسترجعة والمزوّد والتصنيف وزمن الاستجابة للتدقيق في الإدارة. محاكاة «ماذا لو؟» لا تنشئ ادعاءات أو أدلة أو مقاطع معرفة.

## واجهات API

جميعها تحت `/api/v1/`. القوائم مرقّمة بـ24 عنصرًا (`count`, `next`, `previous`, `results`). الأخطاء `{ "error": ..., "status": ... }` في واجهات DRF. واجهات المصادقة تعيد `error` وحالة HTTP المناسبة.

| المسار | الاستخدام |
|---|---|
| `auth/` | GET للجلسة ورمز CSRF |
| `auth/register/`, `auth/login/`, `auth/logout/`, `auth/profile/` | POST للتسجيل والدخول والخروج والملف |
| `events/`, `persons/`, `places/`, `eras/`, `sources/` | قراءة المحتوى المرئي؛ الإدارة فقط تنشئ وتعدل وتؤرشف |
| `events/{id}/graph/`, `events/{id}/claims/` | الخريطة والادعاءات |
| `claims/{id}/evidence/` | تتبّع الادعاء |
| `claims/`, `evidence/`, `relationships/` | CRUD بصلاحيات الإدارة؛ قراءة عامة مرشحة |
| `sources/{id}/process/` | POST، معالجة المصدر للإدارة |
| `sources/{id}/chunks/` | GET، مراجعة المقاطع للإدارة |
| `search/?q=...` | البحث العربي الموحد |
| `ai/ask/` | POST: `question`, `event_id` اختياري |
| `simulations/` | السيناريوهات المنشورة |
| `simulations/{id}/run/` | POST: `acknowledged: true`, `choice` |
| `bookmarks/`, `bookmarks/toggle/` | محفوظات المستخدم الحالي فقط |

استعمل جلسة Django ورمز `X-CSRFToken` من `auth/`، حتى لطلب AI أو محاكاة من زائر. المعدل الافتراضي للأسئلة والمحاكاة مجتمعين 20/ساعة لكل مستخدم أو IP. تسجيل الدخول/الحساب محدود إلى 30 محاولة/ساعة لكل IP.

## قاعدة البيانات والنشر

SQLite للاستخدام المحلي. لتشغيل PostgreSQL:

```dotenv
DATABASE_URL=postgresql://athar:<password>@localhost:5432/athar
```

ثم نفّذ `migrate` و`seed_demo` في القاعدة الجديدة. بذر البيانات ليس نقلًا لقاعدة SQLite.

يتوفر `Dockerfile` و`compose.yaml` لخادم Waitress وقاعدة PostgreSQL واحدة. لتجربة Docker محليًا أضف `POSTGRES_PASSWORD` إلى `.env` واستخدم `DEBUG=true` و`ALLOWED_HOSTS=localhost,127.0.0.1`. شغّل:

```sh
docker compose up --build -d
docker compose exec web python manage.py seed_demo
docker compose exec web python manage.py create_demo_admin
```

لم يُختبر Docker/PostgreSQL حيًا في بيئة التسليم الحالية؛ الاختبارات المنفذة تستخدم SQLite. للإنتاج يلزم HTTPS أمام الخادم، `DEBUG=false`، مفتاح `SECRET_KEY` عشوائي ثابت، مضيفون محددون، ونسخ احتياطية للقاعدة والملفات. عند انتهاء TLS في reverse proxy موثوق اضبط `SECURE_PROXY_SSL_HEADER` بما يناسب البنية بعد التأكد من حجب رؤوس العملاء المزورة. المتغير الافتراضي غير مضبوط عمدًا.

حدود المعدل تستخدم cache الذاكرة المحلية؛ لعدة عمليات/خوادم يلزم cache مشترك أو حدود على مستوى الوكيل. يستعمل الخادم عمليات متزامنة؛ قد يستغرق استخراج مصدر أو استدعاء نموذج عشرات الثواني، فلا يُنصح بملفات كبيرة أو كثافة استخدام عالية دون طابور مهام لاحقًا.

.\.venv\Scripts\python.exe manage.py test tests --noinput

يغطي الاختبار التسجيل ومنع تصعيد الدور، صلاحيات كل الموارد، مسار الإدارة الكامل من TXT إلى إجابة مصدرية، CRUD والنشر والأرشفة، سرية المحفوظات، CSRF للزائر، XSS، البحث العربي، الخريطة، استبعاد المسودات والمصادر الملغاة والتجريبية، مواضع PDF/DOCX/TXT، تزوير الاستشهادات وفشل المزوّد، وفصل المحاكاة وحدود المعدل. `reportlab` اعتماد اختباري فقط لإنشاء PDF صغير أثناء الاختبار.

## حدود النسخة

- تتضمن البيانات المحررة ست محطات، مع تعميق بدر وأُحد والخندق. التحقق هو مطابقة للمقتطفات وصفحات العرض، وليس تحقيقًا مستقلًا للكتب أو لجميع الروايات.
- ملفات PDF المصورة تحتاج OCR خارجيًا. قد يتفاوت ترتيب النص المستخرج من ملفات PDF العربية؛ راجع المقاطع قبل اعتمادها. ترقيم DOCX ليس ثابتًا لذا لا يُخترع رقم صفحة.
- التحقق من المصادر بشري، والتحقق الآلي من الاستشهاد بنيوي وليس تحقيقًا علميًا للمحتوى.
- لا تحتوي النسخة على بريد استعادة كلمة المرور أو تحقق البريد أو تسجيل اجتماعي؛ لم تُطلب هذه الخدمات في MVP.
- الخطوط تُحمّل من Google Fonts مع بدائل نظام محلية؛ بقية الواجهة والبيانات والصورة تعمل محليًا. الصورة الفنية مأخوذة من مواد العرض التي وفرها المستخدم، ولا تمثل مشهدًا تاريخيًا موثقًا.
- لا توجد خدمة استضافة عامة مفعّلة. الرابط المحلي يعمل على الجهاز الذي يشغّل الخادم.

## استوديو المعرفة للأدمن

المسار: `/dashboard/studio/`، أو من زر الاستوديو داخل تحرير الحدث.

1. اختر الحدث، ثم رابط صفحة عامة أو ملف PDF نصي / DOCX / TXT، أو مصدرًا محفوظًا.
2. عاين المقاطع ومواضعها واختر من 1 إلى 12 مقطعًا (بحد 18 ألف حرف). يبقى المصدر الجديد خاصًا غير معتمد.
3. اضغط الاستخراج. تُرسل المقاطع المختارة وسياق المهمة وقائمة الكيانات إلى المزوّد المضبوط على الخادم؛ تظهر هويته قبل الإرسال.
4. راجع المعلومات والفقرات والعناوين والتصنيف والأشخاص والأماكن. الاقتباسات تبقى حرفية؛ يرفض الخادم أي اقتباس غير موجود أو مقطع من مصدر آخر أو كيان لم يُدرج للمراجعة.
5. اختر المقترحات واحفظها كمسودات مترابطة: معلومات، أدلة، فقرات، وأدوار للشخصيات. اعتمد المصدر ثم المعلومات وأدلتها ثم الفقرات. راجع علاقات الشخصيات من «العلاقات» قبل نشرها. عند نشر الفقرة تتحدث روابط مصادر الحدث وأشخاصه وأماكنه المرئية.

مطابقة الاقتباس حرفيًا لا تثبت أن المعنى المستخرج صحيح؛ مراجعة المحرر لازمة قبل النشر. الملفات حتى 10 MB؛ PDF المصور يحتاج OCR مسبقًا. DOCX يحفظ عناوين الأقسام، وPDF يحفظ أرقام الصفحات الفعلية. قارئ المواقع يجلب صفحة نصية واحدة حتى 2 MB / 120 ألف حرف؛ لا يشغّل JavaScript ولا يسجل دخولًا. تُفحص كل عناوين DNS والتحويلات، ويثبت الاتصال على عنوان عام مع تحقق TLS. لا تُجلب عناوين الأجهزة المحلية أو الشبكات الخاصة.

فشل المزوّد يبقي المقاطع ويتيح إعادة المحاولة. في الاختبار الحي بتاريخ 2026-10-02 رفض مشروع Gemini الطلب بـ403، بما في ذلك التجربة من واجهة الاستوديو. أصبح Ollama المحلي متاحًا للاختبار والتوليد بتاريخ 2026-10-03. إعداد `extractive` يتيح قراءة النص لكنه لا يولد سردًا؛ تظهر رسالة صريحة بذلك.

## اختيار اتصال الذكاء الاصطناعي

افتح [إعدادات المزوّدين](http://127.0.0.1:8000/dashboard/ai-providers/)، واختر Ollama أو Gemini أو OpenAI أو خدمة متوافقة مع OpenAI، ثم اكتب رابط API الأساسي واسم النموذج والمفتاح عند الحاجة. احفظ واختبر، ثم فعّل الاتصال الناجح. يشمل التفعيل الأسئلة المسندة والمحاكاة واستخراج السرد وتحليل المصادر الجديدة. تعديل اتصال مفعّل ينشئ بديلًا غير مفعّل إلى أن ينجح اختباره وتختاره.

تُشفّر المفاتيح المحفوظة باستخدام `AI_CREDENTIAL_KEY` أو `SECRET_KEY` عند غيابه، ولا تُعاد في صفحات التحرير. احتفظ بسر التشفير ثابتًا واحتفظ بنسخة احتياطية منه منفصلة عن قاعدة البيانات. لا يُنقل المفتاح المحفوظ عند تغيير البروتوكول أو عنوان API. تستخدم الخدمة الرسمية مفتاح البيئة فقط إذا لم تحفظ مفتاحًا وكان الرابط مطابقًا للرابط الرسمي. تقبل الخدمة المحلية HTTP على loopback فقط؛ تستخدم الاتصالات البعيدة HTTPS، ولا تتبع طلبات API تحويلات HTTP.

اختُبر Ollama فعليًا بنموذج `phi4:latest`: توليد JSON، والتحليل التلقائي من رفع ملف في المتصفح، وربط سجلات موجودة وإنشاء شخصية مسودة، واسترجاع إجابة مع استشهاد صحيح عبر `check_ai`. موصلات المزودين الآخرين لها اختبارات آلية؛ لا يمثل ذلك إثبات اتصال حي بـOpenAI، ولا يزيل رفض مشروع Gemini السابق.

## اعتماد المصادر وتنقية الصفحات وحفظ الإجابات

في تحرير المصدر توجد بطاقة «جاهزية المصدر» وزر «اعتماد المصدر للاسترجاع». يفهرس النص، ويضبط حالته إلى معتمد، ويفعّل استرجاعه في خطوة واحدة. يبقى اعتماد المعلومات المستخرجة وروابط الشخصيات مستقلًا. تفعيل مربع الاعتماد في نموذج التحرير يرفع حالة المسودة أو قيد المراجعة إلى معتمد أيضًا.

زر «معالجة المصدر للاسترجاع» يعمل للملفات والروابط والمصادر التي لها نص محفوظ. عند وجود مقاطع يعيد بناء متجهات الاسترجاع في مكانها دون تغيير النص أو معرفات المقاطع أو الأدلة. إذا لم توجد مقاطع، يستخرج الملف أو يجلب الصفحة. لا يعيد تنزيل المصدر عند إعادة الفهرسة؛ لتنقيح صفحة قديمة استخدم «معاينة نص الصفحة المنقّح». حُسم تعارض اسم مسار الزر مع مسار DRF؛ يعيد الأدمن إلى بطاقة المصدر مع رسالة النتيجة.

قارئ الصفحات يحدد متن المقال/الحدث ويستبعد السكربتات والرأس والقوائم والأشرطة الجانبية والنوافذ المخفية وأزرار المشاركة والبيانات الوصفية الشائعة. في صفحات أحداث الدرر يقرأ حاوية الحدث تحديدًا ويحتفظ بعنوانه وتأريخه ونصه، ويرفض استيراد قوائم الصفحة إذا تغيرت بنيتها ولم يعثر على المتن. تبقى الحواشي والمراجع داخل المتن. بعض المواقع غير المنظمة تحتاج مراجعة المعاينة؛ التنقية ليست ضمانًا لاستخراج مثالي من كل موقع.

المعاينة لا تعدل النص السابق. حفظها ينشئ إصدارًا خاصًا جديدًا مرتبطًا بالسابق عبر `replaces`، ويبدأ تحليله، حتى تبقى الاستشهادات القديمة سليمة. يستطيع المسؤول مراجعة النسخة الجديدة واعتمادها. لا تُدمج اقتراحات النسخة القديمة أو تُنشر تلقائيًا.

يحفظ `AIQueryLog` السؤال والإجابة الكاملة والاستشهادات المنظمة والمزوّد والنموذج وحالة النجاح أو التعذر لكل طلب، بما فيه الزائر. للمستخدم المسجّل رابط «أسئلتي وإجابات أثَر» داخل «رحلتي»، ومن كل إجابة إلى صفحتها المحفوظة في `/library/answers/`. يستطيع الأدمن مراجعة أسئلة الجميع وردودها من سجل الأسئلة، بينما لا يستطيع المستخدم فتح سجل مستخدم آخر. تبقى نسخة الاستشهاد وقت الإجابة محفوظة حتى إذا تغير نص المصدر لاحقًا.

استُعيدت الإجابات القديمة فقط عند وجود زوج سؤال/جواب محفوظ يمكن مطابقته دون التباس. السجلات القديمة التي لم يُحفظ ردها لا تُملأ برد مولّد لاحقًا. لا توجد جلسة متابعة متعددة الرسائل تُرسل سياقها إلى النموذج بعد؛ السجل يحتفظ بكل سؤال وجوابه المستقل. يتطلب سجل المستخدم تسجيل الدخول، وتبقى ردود الزائر في سجل الإدارة.

### استكمال القراءة والتحقق من الترابط

بعد حزم الاستيراد والسرد السابقة: `python manage.py complete_journey` للمعاينة ثم `python manage.py complete_journey --apply` للتطبيق مع نسخة احتياطية. `python manage.py audit_content --strict` يفحص عمق السرد وروابط الشخصيات والأماكن والأدلة للموضوعات المنشورة. تفاصيل المراجعة وحدودها في [CONTENT_REVIEW.md](CONTENT_REVIEW.md).

### تحرير المحتوى من لوحة الإدارة

يمكن إضافة وتعديل وإزالة الأحداث والفقرات والفصول والشخصيات والأماكن والمصادر والمقاطع والأدلة والعلاقات والمحاكاة من [أمانة المعرفة](http://127.0.0.1:8000/dashboard/). افتح الحدث للوصول إلى محتواه المرتبط، واستخدم البحث والتصفية ومربعات اختيار الاستشهادات. الإزالة للأصناف ذات حالة النشر هي أرشفة قابلة للاستعادة، والمقاطع المستخدمة محمية حتى تُنقل أدلتها. [دليل إدارة المحتوى](ADMIN_GUIDE.md) يوضح الحقول ودورة النشر والتصحيح.

تبدأ لوحة الإدارة الآن بمداخل واضحة حسب المهمة وقائمة لما ينتظر المراجعة. تعرض صفحة الحدث مؤشرات الجاهزية والخطوة التالية، وتعرض صفحة المصدر خطوات القراءة والمراجعة والاعتماد والتحليل. النماذج مقسمة، وتتيح الحفظ والعودة إلى سياقها. راجع ADMIN_GUIDE.md لتسلسل نشر الحدث ثم فقراته وكيفية الانتقال من المصدر إلى السرد.
